# Change log: Data Uploader

Date: 2026-10-06
Contributor: Priyavrat Dev Sharma
Email: priyavratsharma1379@gmail.com

## Summary

A third tab named Data Uploader was added next to Harmonize and Inventory Browser. Items can be provided in two ways, and both end in the same review step:

- Option 1: enter items in a form, collect them in a list, then click Review and harmonize.
- Option 2: download a header-only sample CSV, fill it in, upload it, then click Upload.

The review step applies the same rules as Check inventory on the Harmonize tab and shows three tables:

- Items already in the inventory (exact item_id match). Their existing assignment is reused.
- Possible duplicates (same text as an inventory item, different item_id), each with a same_item? checkbox.
- New items.

Run harmonization then runs the model only for the new items, plus any duplicate marked as a different item. It shows a running note and a progress bar, and ends with a results table and a Download harmonized CSV box.

## Validation rules

- All six columns are required: construct, questionnaire, item_id, item_text, answer_options, scoring.
- No cell may be empty. There are no restrictions on the type of cell contents.
- At least one data row is required.
- An item_id must not repeat within a submission.
- The construct must be one of the supported constructs.
- A file in the wrong format produces a clear message that points to the Download sample CSV button.

## Data handling

- Only the new items predicted by the model are added to the harmonized inventory.
- Nothing else is stored. The uploaded rows are not saved to a separate file.
- answer_options and scoring are required and are shown in the preview, but they are not stored because the inventory has no columns for them.

## User interface

- The same_item? checkbox is the first column of the duplicates table.
- All preview tables wrap long text and scroll sideways when the columns do not fit the page.
- Each option has its own preview, progress bar and results directly below its button.
- While harmonization runs, the buttons are disabled and a progress bar shows the current group.
- The results table can be downloaded as harmonized_results.csv.

## New files

- src/harmonica/uploader/__init__.py: package description.
- src/harmonica/uploader/rules.py: validation rules, independent of Gradio.
- src/harmonica/uploader/inventory_check.py: comparison of items with the inventory, shared with the Harmonize tab.
- src/harmonica/uploader/runner.py: harmonization per group and the results file, shared with the Harmonize tab.
- src/harmonica/uploader/tab.py: the Gradio tab and its handlers.
- tests/test_uploader_rules.py: tests for the rules and the inventory check.
- tests/test_data_uploader.py: tests for the tab behaviour.
- log_changes/2026-10-06.md: this file.

## Modified files

src/harmonica/app.py. The Harmonize tab behaves as before. Its inventory check and harmonization logic moved into the shared uploader modules so that both tabs use one implementation:

- The inventory comparison now uses check_items_against_inventory.
- The construct check now uses check_constructs.
- Running harmonization now uses run_groups and decisions_from_review.
- The results file is written by write_results_csv.
- The column lists are shared instead of repeated.
- The module description now mentions three tabs.

One visible difference: the unknown construct error now lists the names in plain text, for example Unknown construct(s): dep. Supported: depression, apathy, and so on. Both tabs share this message.

## Tests

- The full test suite passes, including the existing tests, which were not modified.
- The model is replaced by a stand-in in the tests and in the browser checks. The real models have not yet been run through the uploader.
- Run the tests with: python -m pytest -q

## Known follow-ups

- The command line script and the core library repeat some of the logic that now lives in the shared modules. Consolidating them is a separate decision.
- The list of supported constructs exists in two places in the configuration.
- Several older test files define their own copies of the inventory columns and fixtures.
